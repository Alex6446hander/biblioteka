# Техническое задание на разработку системы управления документами (СУД)

**Версия:** 1.0 (черновик для передачи в разработку)  
**Основание:** исходный документ «СУД2.docx», расшифровка голосового файла «Запись.m4a.txt», рекомендации по открытым вопросам (приняты как рабочие требования, подлежат финальному утверждению заказчиком).

---

## 1. Общие сведения

### 1.1. Назначение системы
Веб-система управления документами (СУД) предназначена для учёта, классификации, хранения и контроля доступа к документам организации с использованием модели, имитирующей физическое хранение (шкафы). Система обеспечивает разграничение прав, проверку совместимости документов и хранилищ, автоматическую архивацию и удаление, ведение журнала действий.

### 1.2. Цели разработки
- Создать конечный продукт (не MVP).
- Обеспечить учёт документов, контроль доступа и архивирование.
- Заменить разрозненное хранение файлов в папках и ручной учёт.

### 1.3. Целевая аудитория
- **Сотрудники организации** (пользователи).
- **Администраторы**.
- Внешние партнёры — не предусмотрены.

### 1.4. Режим эксплуатации
Внутренняя система для небольшой организации. Одновременная работа — до 20 сессий. Объём данных: до 100 пользователей, до 10 000 документов.

## 2. Термины и сущности

| Сущность | Описание |
|---|---|
| **Документ** | Единица информации, подлежащая учёту. Имеет тип, название, описание, файл, метаданные (автор, дата создания, дата изменения), срок жизни (опционально), статус жизненного цикла, владельца. Размещается в шкафу. |
| **Шкаф (хранилище)** | Контейнер для группировки документов. Имеет тип (из 5 фиксированных), название, ёмкость (макс. количество документов), правила доступа, пароль (для конфиденциального типа), владельца, статус (активен / архив). |
| **Полка** | **Не используется.** Отказаться от сущности «полка» в пользу плоской структуры «шкаф → документы». |
| **Ёмкость шкафа** | Максимальное количество документов, которое можно разместить в шкафу. Задаётся при создании. |
| **Матрица совместимости** | Набор правил, определяющих, документы каких типов можно размещать в шкафах каких типов. |
| **Пользователь** | Сотрудник с учётной записью. |
| **Администратор** | Пользователь с расширенными правами. |
| **Лог действий** | Журнал событий системы. |
| **Корзина** | Временное хранилище удалённых документов (для автоудаления и ручного удаления). |
| **Уведомление** | Внутрисистемное сообщение о событии. |

### 2.1. Типы документов
1. **Конфиденциальный документ (ДСП)** — ограниченный доступ, требует пароля шкафа.
2. **Общедоступный документ** — свободное ознакомление, без дополнительных паролей.
3. **Внутренний рабочий документ** — текущее делопроизводство, не публичный, без пароля.
4. **Проектный документ** — привязан к проекту/задаче, имеет срок жизни (дедлайн), после завершения архивируется.
5. **Черновик** — предварительная версия, не имеет юридической силы.

### 2.2. Типы шкафов
1. **Конфиденциальное хранилище** — только конфиденциальные документы, обязательный пароль.
2. **Общее хранилище** — только общедоступные документы.
3. **Номенклатурное хранилище** — только внутренние рабочие документы (аналог номенклатурного дела).
4. **Архив** — долговременное хранение завершённых документов, режим read-only; принимает общедоступные и внутренние рабочие документы.
5. **Временное хранилище** — документы с ограниченным сроком жизни, автоудаление; принимает только внутренние рабочие документы.
6. **Проектное хранилище** — привязано к проекту, имеет дедлайн; после завершения переводится в архив (read-only); принимает любые документы, кроме конфиденциальных.

> **Примечание:** в исходном документе перечислены 6 типов, но сказано «пусть будет 5». В ТЗ фиксируем **6 типов** (все перечисленные), так как они функционально различаются. Это требует подтверждения заказчика.

## 3. Роли и права доступа

### 3.1. Роли
- **Пользователь (Сотрудник)**.
- **Администратор**.

Другие роли (руководитель проекта, аудитор) — не предусмотрены.

### 3.2. Права пользователя
- Создавать документы (указывать название, описание, тип, загружать файл; срок жизни — опционально).
- Размещать документы в шкафах, совместимых по матрице.
- Просматривать свои документы (с учётом пароля для конфиденциальных шкафов).
- Редактировать метаданные своих документов.
- Удалять свои документы (кроме документов в архиве — там read-only).
- Блокировать документ (переводить в статус «Утверждён»).
- Создавать собственные шкафы (только из 6 фиксированных типов).
- Искать и фильтровать свои документы.
- Экспортировать свои данные.
- Видеть только свои документы во всех шкафах, включая общие.
- Получать внутрисистемные уведомления.

### 3.3. Права администратора
- Все права пользователя.
- Создавать, редактировать, удалять любые документы (включая чужие).
- Создавать, редактировать, удалять любые шкафы.
- Управлять пользователями (создавать аккаунты, блокировать, менять пароли).
- Просматривать список всех документов, включая конфиденциальные (без ограничений).
- Входить в любые шкафы, включая конфиденциальные, **без пароля** (bypass). Каждое такое открытие логируется с пометкой «admin bypass».
- Просматривать логи действий пользователей.
- Настраивать глобальные параметры (лимиты, сроки автоудаления, срок хранения корзины).
- Управлять импортом/экспортом.

> **Важно:** это правило изменяет исходный документ, где было сказано, что администратор не может входить в секретные хранилища других пользователей без пароля. В голосовом ответе заказчик подтвердил обратное. Требуется финальное утверждение.

## 4. Функциональные требования

### 4.1. Аутентификация и профиль
- Регистрация/вход по логину и паролю.
- Смена пароля.
- Просмотр профиля.
- Пароли хранятся в виде **bcrypt-хеша**.

### 4.2. Модуль работы с документами
- **Создание документа:** форма с полями: название (обязательно), описание (обязательно), тип документа (обязательно), файл (обязательно), срок жизни (опционально). Владелец — текущий пользователь.
- **Размещение документа:** пользователь вручную выбирает шкаф из списка **совместимых** шкафов. Несовместимые шкафы не отображаются. При попытке размещения в неподходящий шкаф (если такое стало возможно через API) — ошибка.
- **Просмотр документа:** карточка с метаданными и ссылкой на файл. Для конфиденциальных шкафов — запрос пароля шкафа (кроме администратора).
- **Редактирование метаданных:** название, описание, срок жизни (для своих документов; в архиве — запрещено).
- **Удаление документа:** перемещение в корзину (для своих документов; в архиве — запрещено). Окончательное удаление — через корзину.
- **Блокировка документа:** перевод в статус «Утверждён» (владельцем или администратором).
- **Статусы жизненного цикла:** Черновик → Активный → Утверждён → Архивный. Переходы: создание (Черновик или Активный в зависимости от типа), утверждение (Утверждён), архивация (Архивный) — автоматически для проектных шкафов.

### 4.3. Модуль шкафов
- **Создание шкафа:** пользователь или администратор. Поля: название, тип (из 6), ёмкость (целое число > 0), пароль (только для конфиденциального типа). Владелец — создатель.
- **Правила типа шкафа** (кто имеет доступ, какие действия разрешены, какие документы можно класть) задаются автоматически по типу.
- **Заполненность:** прогресс-бар `занято / ёмкость`.
- **Страница шкафа:** список документов (только свои для пользователя, все для администратора), правила шкафа, заполненность, кнопки управления (для владельца/админа).
- **Переполнение:** при попытке положить документ в заполненный шкаф — ошибка и диалог с действиями: «Удалить старые документы» (открывает список документов шкафа) или «Создать новый шкаф».
- **Архивация шкафа:** проектный шкаф по дедлайну автоматически переводится в статус «Архив» (read-only). Владелец получает уведомление за 3 дня.
- **Удаление шкафа:** только владелец или администратор. При удалении шкафа документы перемещаются в корзину.

### 4.4. Матрица совместимости
Таблица правил (тип документа → допустимые типы шкафов):

| Тип документа | Допустимые типы шкафов |
|---|---|
| Конфиденциальный | Конфиденциальное |
| Общедоступный | Общее, Архив, Проектное |
| Внутренний рабочий | Номенклатурное, Архив, Временное |
| Проектный | Проектное |
| Черновик | Номенклатурное, Временное |

> Проверка выполняется на уровне бизнес-логики. При нарушении — ошибка с текстовым пояснением (например, «Нельзя поместить конфиденциальный документ в общее хранилище»).

### 4.5. Поиск, фильтры, сортировка
- **Поиск:** по названию и описанию (регистронезависимый). Полнотекстовый поиск по содержимому файлов — **не делать**.
- **Фильтры:**
  - тип документа;
  - статус (Черновик / Активный / Утверждён / Архивный);
  - шкаф;
  - владелец (только для администратора);
  - дата создания (диапазон);
  - дата изменения (диапазон);
  - срок жизни (есть / истекает / истёк).
- **Сортировка:** название, дата создания, дата изменения, срок жизни, тип, статус (по возрастанию/убыванию).
- **Сохранение фильтров:** не требуется (только в рамках сессии).

### 4.6. Автоматические процессы
- **Автоудаление из временного хранилища:**
  1. За 3 дня до истечения срока — уведомление владельцу.
  2. В день истечения — документ перемещается в корзину.
  3. В корзине хранится 7 дней (настраивается администратором).
  4. Затем удаляется окончательно.
  5. Все шаги логируются.
- **Автоархивация проектного шкафа:**
  1. За 3 дня до дедлайна — уведомление владельцу.
  2. В день дедлайна — шкаф переводится в статус «Архив» (read-only).
  3. Уведомление администратору — не отправляется.
- **Уведомления:** только внутрисистемные (иконка колокольчика). События:
  - документ скоро будет удалён;
  - документ перемещён в корзину;
  - проектный шкаф скоро архивируется;
  - шкаф переполнен (при попытке размещения);
  - ошибка импорта.

### 4.7. Экспорт / импорт
- **Экспорт:**
  - список документов → **CSV** (метаданные);
  - отдельный документ → **PDF** (карточка с метаданными; вложение — если файл PDF/изображение, иначе ссылка);
  - дамп данных пользователя → **JSON** (опционально).
- **Импорт:**
  - загрузка ZIP-архива с `manifest.json` и папкой `files/`;
  - система валидирует манифест, проверяет матрицу совместимости, раскладывает документы по шкафам;
  - формирует отчёт: загружено / отклонено / причина.

### 4.8. Логирование
- Логировать **все** события: вход/выход, создание/редактирование/удаление документов, создание/удаление шкафов, изменение прав, открытие конфиденциальных шкафов (включая admin bypass), импорт/экспорт, автоудаление, автоархивация.
- Формат: дата/время, пользователь, действие, объект, результат.
- Просмотр логов — только администратор.

### 4.9. Управление пользователями (админ)
- Создание аккаунтов.
- Блокировка/разблокировка.
- Смена пароля.
- Назначение роли (пользователь/администратор).

## 5. Структура сайта и интерфейс

### 5.1. Основные страницы
1. **Главная страница** — название проекта, форма входа (или приветствие для авторизованных).
2. **Профиль** — данные пользователя, смена пароля.
3. **Личный кабинет:**
   - **Мои документы** — список с фильтрами и сортировкой, кнопка «Создать документ».
   - **Мои шкафы** — список шкафов с прогресс-барами, кнопка «Создать шкаф».
   - **Корзина** — удалённые документы.
   - **Уведомления** — список.
4. **Страница шкафа** — правила, заполненность, список документов (свои/все), действия.
5. **Страница документа** — метаданные, файл, действия (редактировать, удалить, блокировать).
6. **Поиск** — глобальная строка поиска (доступна из шапки).
7. **Админ-панель** (только для администратора):
   - **Пользователи** — управление.
   - **Шкафы** — управление всеми шкафами.
   - **Глобальные настройки** — лимиты, сроки автоудаления, срок хранения корзины.
   - **Логи** — просмотр.
   - **Импорт/экспорт** — управление.

### 5.2. Навигация
- Иерархическое дерево: **Шкафы → Документы** (в левой панели или на странице шкафа).
- Хлебные крошки.
- Верхнее меню: Главная, Личный кабинет, Поиск, Уведомления, Профиль, Админ-панель (для админа).

### 5.3. Визуализация
- Шкафы — **списком**, без графической имитации физического шкафа.
- Заполненность — **прогресс-бар**.
- Стиль — **деловой, утилитарный**.
- Адаптивность — **не требуется** (но резиновая вёрстка приветствуется).
- Многоязычность — **нет** (только русский).

### 5.4. Дашборды
- **Пользователь:** количество моих документов по типам; мои шкафы и их заполненность; документы с истекающим сроком (7 дней); последние 5 действий.
- **Администратор:** общее число пользователей, документов, шкафов; топ-5 заполненных шкафов; документы в корзине; последние 20 записей лога; ошибки импорта за 7 дней.

## 6. Технические требования

### 6.1. Стек
- **Backend:** Python (FastAPI или Django).
- **БД:** PostgreSQL.
- **ORM:** SQLAlchemy (при FastAPI) или Django ORM.
- **PDF:** `reportlab` или `weasyprint`.
- **Аутентификация:** сессии или JWT (на усмотрение разработчика).
- **Пароли:** bcrypt.

### 6.2. Безопасность
- HTTPS обязательно.
- Защита от CSRF, SQL-инъекций (через ORM).
- Хеширование паролей.
- Логирование критичных действий.
- Разграничение прав на уровне API.

### 6.3. Производительность
- До 100 пользователей, до 10 000 документов, до 20 одновременных сессий.
- Время отклика — до 2 секунд на типовые операции.

### 6.4. Браузеры
- Последние версии Chrome, Firefox, Edge. Safari — по возможности.

### 6.5. Резервное копирование
- Не предусмотрено в первой версии (по усмотрению администратора).

---

## 7. Ограничения и нефункциональные требования

- **Не делать:** полнотекстовый поиск по содержимому файлов, мобильную версию, многоязычность, публичный API, сохранение пользовательских фильтров, графическую имитацию шкафов, полки как сущность.
- **Срок жизни документа** — необязательное поле.
- **Полки** — исключены.
- **Ёмкость** — максимальное количество документов.
- **Выбор шкафа** — только вручную из совместимых.
- **Переполнение** — блокировка + диалог.
- **Пароли шкафов** — хеш, сброс только через администратора.
- **Автоудаление** — через корзину (7 дней).
- **Уведомления** — только внутрисистемные.

## 9. Примечания для заказчика

1. **Спорные пункты, требующие финального утверждения:**
   - Администратор входит в конфиденциальные шкафы без пароля (изменение исходного документа).
   - Количество типов шкафов: 6 (в исходном документе было противоречие «5»).
   - Полки исключены.
   - Видимость в общих шкафах: только свои документы.
   - Пароли хранятся в виде хеша.
   - Автоудаление через корзину на 7 дней.
